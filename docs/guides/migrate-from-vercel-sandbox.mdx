Vercel Sandbox and Superserve sandboxes do the same job: run untrusted code in an isolated environment that you control from an SDK. Most code moves call by call.

## Ready to switch

Pick how you want to migrate. Do it yourself step by step, or give the prompt to a coding agent and let it change your code.

```bash TypeScript
export SUPERSERVE_API_KEY=ss_live_...
```

<Step title="Map the API">

The main changes: every sandbox needs a `name` and you keep its `id`, a command is one shell string instead of a command and an argument list, times are in seconds, and a timeout pauses the sandbox instead of stopping it. The Vercel column shows `@vercel/sandbox` calls.

<Tabs>
<Tab title="TypeScript">

| Task | Vercel Sandbox | Superserve |
| --- | --- | --- |
| Create | `Sandbox.create({ name, image, timeout, env, tags })` | `Sandbox.create({ name, fromTemplate, timeoutSeconds, envVars, metadata })`. `name` is required. Keep `sbx.id` to reconnect. |
| Image | `image: "my-repo:v1"` or `runtime: "node24"` | `Template.create({ name, from: img, steps: [{ run }] })`, built once. Then `fromTemplate: name`. The default `superserve/base` template has Node.js, Python and Git. |
| Source code | `source: { type: "git", url, depth, revision }` | `sbx.commands.run("git clone --depth 1 --branch <revision> <url> /home/user/app")` for a branch or tag. For a commit, run `git fetch --depth 1 origin <sha> && git checkout FETCH_HEAD` in the clone. Or clone in a template step. |
| Reconnect | `Sandbox.get({ name })` | `Sandbox.connect(id)`. Resumes a paused sandbox automatically. |
| Run a command | `sandbox.runCommand({ cmd, args, cwd, env })`, then `await result.stdout()` | `sbx.commands.run(cmd, { cwd, env, timeoutMs })` returns `exitCode`, `stdout` and `stderr`. Without `timeoutMs`, the call waits 30 seconds. |
| Run as root | `runCommand({ cmd, args, sudo: true })` | Commands run as `root` by default. Pass `user` to run as another user. |
| Background process | `runCommand({ cmd, args, detached: true })`, then `wait()` / `kill()` | `sbx.commands.spawn(cmd)`, then `wait()` / `kill()` |
| Files | `sandbox.writeFiles([{ path, content }])` / `readFileToBuffer({ path })` | `sbx.files.write(path, data)` / `read(path)`, one file per call |
| Snapshot | `sandbox.snapshot()`, then `Sandbox.create({ source: { type: "snapshot", snapshotId } })`. Stops the sandbox. | `sbx.snapshot()`, then `Sandbox.create({ name, fromSnapshot })`. Saves memory and disk; the sandbox keeps running. |
| Fork | `Sandbox.fork({ sourceSandbox })` | `sbx.snapshot()`, then `Sandbox.create({ name, fromSnapshot })`. Forks keep running processes. |
| Stop and resume | `sandbox.stop()`, then `Sandbox.get({ name })`. Running processes end. | `sbx.pause()` / `sbx.resume()`. Pause keeps memory and running processes. |
| Timeout | `timeout` in milliseconds, `extendTimeout(ms)`. Stops the sandbox. | `timeoutSeconds`, `sbx.update({ timeoutSeconds })`. Pauses the sandbox. Also `idleTimeoutSeconds`. |
| Resources | `resources: { vcpus }` | `vcpu` and `memoryMib` on `Template.create` |
| Network rules | `networkPolicy: { allow: [...] }` or `"deny-all"` | `network: { allowOut: [...hosts, "1.1.1.1/32", "8.8.8.8/32"], denyOut: ["0.0.0.0/0"] }`. Keep the two DNS resolvers in `allowOut`, or the allowed hosts do not resolve. See [Network rules](/sandbox/networking). |
| Public URL | `ports: [3000]` on create, then `sandbox.domain(3000)` | `await sbx.publishPreviewPort(3000)`, then `sbx.getPreviewUrl(3000)`. Publish a port at any time. Pass `{ access: "private" }` to require a preview token. See [Preview URLs](/sandbox/preview-urls). |
| List and delete | `Sandbox.list({ tags })` / `sandbox.delete()` | `Sandbox.list({ metadata })` / `sbx.kill()` |

<Step title="Update your code">

Change the import, add a `name`, convert milliseconds to seconds, and join each command and its arguments into one shell string. Shell-escape each argument, so that the shell does not expand `$VAR`, `*` or quotes. Set a command timeout for long commands such as installs and tests.

<CodeGroup>
```ts Before (Vercel Sandbox)
import { Sandbox } from "@vercel/sandbox"

const sandbox = await Sandbox.create({
  source: { type: "git", url: "https://github.com/your-org/your-app.git" },
  ports: [3000],
  timeout: 600_000,
  env: { NODE_ENV: "test" },
  tags: { team: "infra" },
})
await sandbox.runCommand("npm", ["install"])
const result = await sandbox.runCommand("npm", ["test"])
console.log(await result.stdout())
const url = sandbox.domain(3000)
const snap = await sandbox.snapshot()
const fork = await Sandbox.create({
  source: { type: "snapshot", snapshotId: snap.snapshotId },
})
```

```ts After (Superserve)
import { Sandbox } from "@superserve/sdk"

const sbx = await Sandbox.create({
  name: "ci-run",
  fromTemplate: "superserve/base",
  timeoutSeconds: 600,
  envVars: { NODE_ENV: "test" },
  metadata: { team: "infra" },
})
await sbx.commands.run(
  "git clone --depth 1 https://github.com/your-org/your-app.git /home/user/app",
  { timeoutMs: 120_000 },
)
const result = await sbx.commands.run("npm install && npm test", {
  cwd: "/home/user/app",
  timeoutMs: 300_000,
})
console.log(result.stdout)
await sbx.publishPreviewPort(3000)
const url = sbx.getPreviewUrl(3000)
const snap = await sbx.snapshot()
const fork = await Sandbox.create({ name: "fork", fromSnapshot: snap })
```

```python After (Superserve, Python)
from superserve import Sandbox

sbx = Sandbox.create(
    name="ci-run",
    from_template="superserve/base",
    timeout_seconds=600,
    env_vars={"NODE_ENV": "test"},
    metadata={"team": "infra"},
)
sbx.commands.run(
    "git clone --depth 1 https://github.com/your-org/your-app.git /home/user/app",
    timeout_seconds=120,
)
result = sbx.commands.run(
    "npm install && npm test", cwd="/home/user/app", timeout_seconds=300
)
print(result.stdout)
sbx.publish_preview_port(3000)
url = sbx.get_preview_url(3000)
snap = sbx.snapshot()
fork = Sandbox.create(name="fork", from_snapshot=snap)
```

<Step title="Move existing sandboxes with the migration script">

The script copies `/vercel/sandbox` from each running or persistent Vercel sandbox into `/home/user` in a new Superserve sandbox. It does not change or delete your Vercel sandboxes. Run it with Node.js and the Vercel credentials you use today (`VERCEL_OIDC_TOKEN`, or `VERCEL_TOKEN`, `VERCEL_TEAM_ID` and `VERCEL_PROJECT_ID`) and `SUPERSERVE_API_KEY` set.

```ts migrate-from-vercel-sandbox.ts
import { Sandbox } from "@superserve/sdk"
import { Sandbox as Vercel } from "@vercel/sandbox"

const SRC = "/vercel/sandbox" // directory to copy from each Vercel sandbox
const DST = "/home/user" // directory to copy into in Superserve
const TEMPLATE = "superserve/base" // or the template you built from your Vercel image
const ARCHIVE = "/tmp/state.tgz"
const TIMEOUT_MS = 10 * 60 * 1000 // limit for each upload and extract

for await (const info of await Vercel.list()) {
  // A stopped sandbox that is not persistent has no files to copy.
  if (info.status !== "running" && !info.persistent) continue
  const src = await Vercel.get({ name: info.name })
  const tar = await src.runCommand("tar", ["czf", ARCHIVE, "-C", SRC, "."])
  if (tar.exitCode !== 0) {
    console.error(`${info.name}: archive failed: ${await tar.stderr()}`)
    process.exitCode = 1
    continue
  }
  const tgz = await src.readFileToBuffer({ path: ARCHIVE })
  if (!tgz) {
    console.error(`${info.name}: archive not found`)
    process.exitCode = 1
    continue
  }

  const dst = await Sandbox.create({
    name: `from-vercel-${info.name}`,
    fromTemplate: TEMPLATE,
    metadata: { ...info.tags, migrated_from: info.name },
  })
  await dst.files.write(ARCHIVE, tgz, { timeoutMs: TIMEOUT_MS })
  const out = await dst.commands.run(`tar xzf ${ARCHIVE} -C ${DST}`, {
    timeoutMs: TIMEOUT_MS,
  })
  if (out.exitCode !== 0) {
    console.error(`${info.name}: copy failed: ${out.stderr}`)
    process.exitCode = 1
    continue
  }
  console.log(`${info.name} -> ${dst.id}`)
}
```

The script uses `@vercel/sandbox`, so it runs in Node.js even if your app uses the Python SDK. Each upload and extract can take up to 10 minutes. For large directories or slow connections, raise `TIMEOUT_MS`.

The script copies files. Start your services in the new sandbox, then take a Superserve [snapshot](/sandbox/snapshots) to save memory, processes and disk together.

</Step>

## Known differences

| Area | What to do |
| --- | --- |
| Timeout behavior | Vercel stops a sandbox at its timeout, which ends its processes. Superserve pauses it, keeps memory and processes, and stops compute billing. Call `kill()` or set `autoDeleteSeconds` if you want it gone. |
| Commands | `commands.run` takes one shell string, not a command and an argument list. It returns `stdout` and `stderr` as strings and does not throw on a nonzero exit code. Check `exitCode` / `exit_code`. |
| Sandbox ID | Superserve reconnects by `id`. Names label sandboxes and do not have to be unique. |
| Home directory | Vercel sandboxes use `/vercel/sandbox`. Superserve sandboxes use `/home/user`. Update hard-coded paths. |
| Preview ports | Publish a port with `publishPreviewPort` before you use its URL. A new port is public by default. Publish with `access: "private"` and send a preview token to keep a port protected. Serve on a port from 1024 to 65535. |
| Process state | The migration script moves files, not memory. Take a Superserve snapshot after you restart services. |
