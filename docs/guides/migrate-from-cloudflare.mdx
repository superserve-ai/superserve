<Step title="Install the SDK and set your API key">

Install the Superserve SDK and set `SUPERSERVE_API_KEY` in your environment and CI secrets.

<CodeGroup>
```bash TypeScript
npm install @superserve/sdk

```


</Step>
<Step title="Map the API">

The main changes: Superserve is an API that you call from any backend, so you need no Durable Object or container configuration. A Dockerfile becomes a template, every sandbox gets an `id` that you keep, and an idle sandbox pauses with its memory and disk. The Cloudflare columns show Sandbox SDK 0.12 calls on the `sandbox` stub and 1.0 calls on `this.ctx.container`.

<Tabs>
<Tab title="TypeScript">

| Task | Cloudflare 0.12 | Cloudflare 1.0 | Superserve |
| --- | --- | --- | --- |
| Create | `getSandbox(env.Sandbox, id)` | `env.SANDBOX.getByName(id)`, then `container.start({ image, env })` | `Sandbox.create({ name, fromTemplate, envVars, metadata })`. Keep `sbx.id` and reconnect with `Sandbox.connect(id)`. |
| Image | `FROM docker.io/cloudflare/sandbox` in a Dockerfile | A Dockerfile with `sandbox-shim` | `Template.create({ name, from: img, steps: [{ run }] })`, built once. Then `fromTemplate: name`. The default `superserve/base` template has Node.js, Python and Git. |
| Run a command | `sandbox.exec(cmd, { cwd, env, timeout })` | `container.exec(argv, { cwd, env })`, then `await proc.output()` | `sbx.commands.run(cmd, { cwd, env, timeoutMs })` returns `exitCode`, `stdout` and `stderr` as strings |
| Stream output | `sandbox.execStream(cmd)` | `proc.stdout` | `sbx.commands.run(cmd, { onStdout, onStderr })` |
| Background process | `sandbox.startProcess(cmd)` | `container.exec(argv, { stdout: "ignore" })` and your own process tracking | `sbx.commands.spawn(cmd)`, then `wait()` / `kill()` |
| Files | `sandbox.writeFile(path, content)` / `readFile(path)` | `new Files(container).writeFile(path, content)` / `readFile(path)` | `sbx.files.write(path, data)` / `read(path)` / `readText(path)` |
| Git | `sandbox.gitCheckout(url, { targetDir })` | `container.exec(["git", "clone", url, dir])` | `sbx.commands.run("git clone --depth 1 <url> /home/user/app")` |
| Run code | `sandbox.runCode(code)` | A kernel that you start in the container | `sbx.files.write("/home/user/main.py", code)`, then `sbx.commands.run("python3 /home/user/main.py")` |
| Save state | `sandbox.createBackup({ dir })` / `restoreBackup(backup)` | `DirectoryBackup` or `container.snapshotContainer()` | `sbx.snapshot()`, then `Sandbox.create({ name, fromSnapshot })`. Saves memory and disk; forks keep running processes. |
| Idle timeout | `sleepAfter`, default `"10m"`. `keepAlive: true` to stay awake. | `container.setInactivityTimeout(ms)` | `idleTimeoutSeconds`. Off by default. Pauses the sandbox and keeps memory, processes and disk. `sbx.pause()` / `sbx.resume()` at any time. |
| Env vars and secrets | `envVars` or `setEnvVars()`. Credentials added by `outboundByHost` handlers. | `start({ env })` and an outbound `WorkerEntrypoint` | `envVars` on create, `env` per command, `secrets: { ENV_VAR: "secret-name" }`. The real key never enters the sandbox. See [Secrets](/secrets/overview). |
| Network rules | `enableInternet`, `allowedHosts`, `deniedHosts` | `start({ enableInternet })` and an outbound `WorkerEntrypoint` | `network: { allowOut: [...], denyOut: ["0.0.0.0/0"] }`. Accepts domains and CIDRs. See [Network rules](/sandbox/networking). |
| Buckets | `sandbox.mountBucket(bucket, path, options)` | `S3Mount` | A FUSE driver in a template. See [Cloud buckets](/storage/cloud-buckets). |
| Public URL | `sandbox.exposePort(port, { hostname })` and `proxyToSandbox()` on your wildcard domain | Your Worker routes to `container.getTcpPort(port)` | `await sbx.publishPreviewPort(port, { access: "private" })`, then `sbx.getPreviewUrl(port)`. For the token, use `await sbx.getPreviewToken(port)` (send `token` in the returned `header`) or `await sbx.getSignedPreviewUrl(port)` for a browser. No DNS or routing to set up. See [Preview URLs](/sandbox/preview-urls). |
| List and delete | IDs that your app keeps / `sandbox.destroy()` | IDs that your app keeps / `container.destroy()` | `Sandbox.list({ metadata })` / `sbx.kill()` |

<Step title="Update your code">

Replace the sandbox stub or Durable Object with `Sandbox`, add a `name`, and change paths under `/workspace` to `/home/user`.

<CodeGroup>
```ts Before (Cloudflare 0.12)
import { getSandbox, type Sandbox } from "@cloudflare/sandbox"
export { Sandbox } from "@cloudflare/sandbox"

type Env = { Sandbox: DurableObjectNamespace<Sandbox> }

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const sandbox = getSandbox(env.Sandbox, "ci-run", { sleepAfter: "10m" })
    await sandbox.setEnvVars({ MODE: "ci" })
    await sandbox.gitCheckout("https://github.com/your-org/your-app.git", {
      targetDir: "/workspace/app",
    })
    const result = await sandbox.exec("npm install && npm test", {
      cwd: "/workspace/app",
    })
    const { hostname } = new URL(request.url)
    const { url } = await sandbox.exposePort(3000, { hostname })
    const backup = await sandbox.createBackup({ dir: "/workspace/app" })
    await getSandbox(env.Sandbox, "fork").restoreBackup(backup)
    return Response.json({ stdout: result.stdout, url })
  },
}
```

```ts Before (Cloudflare 1.0)
import { DurableObject } from "cloudflare:workers"

interface Env {
  SANDBOX: DurableObjectNamespace<Sandbox>
}

export class Sandbox extends DurableObject<Env> {
  async test(): Promise<string> {
    const container = this.ctx.container
    if (!container) throw new Error("The container binding is not configured")
    if (!container.running) {
      container.start({ image: container.images.sandbox, env: { MODE: "ci" } })
      await container.setInactivityTimeout(10 * 60 * 1000)
    }
    const app = "/workspace/app"
    const repo = "https://github.com/your-org/your-app.git"
    await (await container.exec(["git", "clone", repo, app])).output()
    const proc = await container.exec(["bash", "-c", "npm install && npm test"], {
      cwd: app,
      env: { MODE: "ci" },
    })
    const { stdout } = await proc.output()
    return new TextDecoder().decode(stdout)
  }
}

export default {
  async fetch(_request, env) {
    return new Response(await env.SANDBOX.getByName("ci-run").test())
  },
} satisfies ExportedHandler<Env>
```

<Step title="Move existing sandboxes with the migration script">

A Cloudflare sandbox is reachable only through your Worker. First add a temporary export route to the Worker. The route archives `/workspace` in one sandbox and returns the archive. Protect it with a `MIGRATION_TOKEN` secret.

<CodeGroup>
```ts Export route (Cloudflare 0.12)
import { getSandbox, type Sandbox } from "@cloudflare/sandbox"

type Env = { Sandbox: DurableObjectNamespace<Sandbox>; MIGRATION_TOKEN: string }

// Call this from your fetch handler for requests to /migrate/export.
export async function exportSandbox(request: Request, env: Env): Promise<Response> {
  if (request.headers.get("Authorization") !== `Bearer ${env.MIGRATION_TOKEN}`) {
    return new Response("unauthorized", { status: 401 })
  }
  const id = new URL(request.url).searchParams.get("id") ?? ""
  const sandbox = getSandbox(env.Sandbox, id)
  const tar = await sandbox.exec("tar czf /tmp/state.tgz -C /workspace .")
  if (!tar.success) return new Response(tar.stderr, { status: 500 })
  const file = await sandbox.readFile("/tmp/state.tgz", { encoding: "base64" })
  return new Response(Uint8Array.from(atob(file.content), (c) => c.charCodeAt(0)))
}
```

```ts Export route (Cloudflare 1.0)
import { Files } from "@cloudflare/sandbox"
import { DurableObject } from "cloudflare:workers"

interface Env {
  SANDBOX: DurableObjectNamespace<Sandbox>
  MIGRATION_TOKEN: string
}

export class Sandbox extends DurableObject<Env> {
  // Add this method to your Durable Object class.
  async exportArchive(): Promise<Response> {
    const container = this.ctx.container
    if (!container?.running) return new Response("not running", { status: 404 })
    const args = ["tar", "czf", "/tmp/state.tgz", "-C", "/workspace", "."]
    const { exitCode, stderr } = await (await container.exec(args)).output()
    if (exitCode !== 0) return new Response(stderr, { status: 500 })
    return new Files(container).readFile("/tmp/state.tgz")
  }
}

// Call this from your fetch handler for requests to /migrate/export.
export async function exportSandbox(request: Request, env: Env): Promise<Response> {
  if (request.headers.get("Authorization") !== `Bearer ${env.MIGRATION_TOKEN}`) {
    return new Response("unauthorized", { status: 401 })
  }
  const id = new URL(request.url).searchParams.get("id") ?? ""
  return env.SANDBOX.getByName(id).exportArchive()
}
```
</CodeGroup>

Then run the script with the sandbox IDs that your app passes to `getSandbox()` or `getByName()`. The script copies each archive into `/home/user` in a new Superserve sandbox. It does not change or delete your Cloudflare sandboxes. Set `CLOUDFLARE_EXPORT_URL` to the full URL of the route, and set `MIGRATION_TOKEN` and `SUPERSERVE_API_KEY`.

<CodeGroup>
```ts migrate-from-cloudflare.ts
import { Sandbox } from "@superserve/sdk"

const EXPORT_URL = process.env.CLOUDFLARE_EXPORT_URL // https://<your-worker>/migrate/export
const TOKEN = process.env.MIGRATION_TOKEN
const DST = "/home/user" // directory to copy into in Superserve
const TEMPLATE = "superserve/base" // or the template you built from your Dockerfile
const TIMEOUT_MS = 10 * 60 * 1000 // limit for each upload and extract

for (const id of process.argv.slice(2)) {
  const res = await fetch(`${EXPORT_URL}?id=${encodeURIComponent(id)}`, {
    headers: { Authorization: `Bearer ${TOKEN}` },
  })
  if (!res.ok) {
    console.error(`${id}: export failed: ${res.status} ${await res.text()}`)
    process.exitCode = 1
    continue
  }
  const tgz = new Uint8Array(await res.arrayBuffer())

  const dst = await Sandbox.create({
    name: `from-cloudflare-${id}`,
    fromTemplate: TEMPLATE,
    metadata: { migrated_from: id },
  })
  await dst.files.write("/tmp/state.tgz", tgz, { timeoutMs: TIMEOUT_MS })
  const out = await dst.commands.run(`tar xzf /tmp/state.tgz -C ${DST}`, {
    timeoutMs: TIMEOUT_MS,
  })
  if (out.exitCode !== 0) {
    console.error(`${id}: copy failed: ${out.stderr}`)
    process.exitCode = 1
    continue
  }
  console.log(`${id} -> ${dst.id}`)
}
```

```python migrate_from_cloudflare.py
import os
import sys
import urllib.error
import urllib.parse
import urllib.request

from superserve import Sandbox

EXPORT_URL = os.environ["CLOUDFLARE_EXPORT_URL"]  # https://<your-worker>/migrate/export
TOKEN = os.environ["MIGRATION_TOKEN"]
DST = "/home/user"  # directory to copy into in Superserve
TEMPLATE = "superserve/base"  # or the template you built from your Dockerfile
TIMEOUT_SECONDS = 10 * 60  # limit for each upload and extract
failed = False

for sandbox_id in sys.argv[1:]:
    url = f"{EXPORT_URL}?id={urllib.parse.quote(sandbox_id)}"
    request = urllib.request.Request(url, headers={"Authorization": f"Bearer {TOKEN}"})
    try:
        with urllib.request.urlopen(request) as res:
            tgz = res.read()
    except urllib.error.URLError as err:
        print(f"{sandbox_id}: export failed: {err}", file=sys.stderr)
        failed = True
        continue

    dst = Sandbox.create(
        name=f"from-cloudflare-{sandbox_id}",
        from_template=TEMPLATE,
        metadata={"migrated_from": sandbox_id},
    )
    dst.files.write("/tmp/state.tgz", tgz, timeout=TIMEOUT_SECONDS)
    out = dst.commands.run(
        f"tar xzf /tmp/state.tgz -C {DST}", timeout_seconds=TIMEOUT_SECONDS
    )
    if out.exit_code != 0:
        print(f"{sandbox_id}: copy failed: {out.stderr}", file=sys.stderr)
        failed = True
        continue
    print(f"{sandbox_id} -> {dst.id}")

sys.exit(1 if failed else 0)
```
</CodeGroup>

For example, run `npx tsx migrate-from-cloudflare.ts user-123 user-456`. Run the script while the sandboxes are awake. A Cloudflare sandbox that went to sleep starts again with an empty disk, so restore its backup first.

Each upload and extract can take up to 10 minutes. For large directories or slow connections, raise `TIMEOUT_MS` / `TIMEOUT_SECONDS`.

The script copies files. Start your services in the new sandbox, then take a Superserve [snapshot](/sandbox/snapshots) to save memory, processes and disk together.

## Known differences

| Area | What to do |
| --- | --- |
| Where your code runs | Cloudflare sandboxes are Durable Objects inside your Worker. Superserve is an API, so call it from your Worker, a server, CI or a notebook. |
| Sandbox ID | Cloudflare uses the ID that you pass to `getSandbox()`. Superserve gives each sandbox an `id` on create. Store it, or set your ID in `metadata` and find the sandbox with `Sandbox.list({ metadata })`. |
| Idle behavior | Cloudflare stops an idle sandbox after 10 minutes by default, and the next start has a fresh disk. By default, a Superserve sandbox does not pause for being idle. Set `idleTimeoutSeconds` to pause it with its memory, processes and disk. |
| Commands | `commands.run` takes one shell string, as 0.12 `exec()` did. It returns `stdout` and `stderr` as strings and does not throw on a nonzero exit code. Check `exitCode` / `exit_code`. |
| Home directory | Cloudflare sandboxes use `/workspace`. Superserve sandboxes use `/home/user`. Update hard-coded paths. |
| Preview ports | Each published port gets its own URL, with no DNS or Worker route to set up. A new port is public by default. Publish with `access: "private"` and send a preview token to keep a port protected. Serve on a port from 1024 to 65535. |
| Process state | The migration script moves files, not memory. Take a Superserve snapshot after you restart services. |
