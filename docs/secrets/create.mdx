A secret needs a **name**, a **value** (the real credential), and a way to authenticate — either a [provider shortcut](#provider-shortcuts) or a [custom auth config](#custom-secrets). The value is encrypted on the platform and never returned by the API.

## Provider shortcuts

The fastest path. A shortcut sets the auth scheme and allowed hosts for a known service, so you supply only a name and value:

<CodeGroup>
```typescript TypeScript
import { Secret } from "@superserve/sdk"

const secret = await Secret.create({
  name: "openai-prod",
  value: process.env.OPENAI_API_KEY!,
  provider: "openai",
})

console.log(secret.hosts)  // ["api.openai.com"]
```

```python Python
import os

from superserve import Secret

secret = Secret.create(
    name="openai-prod",
    value=os.environ["OPENAI_API_KEY"],
    provider="openai",
)

print(secret.hosts)  # ["api.openai.com"]
```
</CodeGroup>

Built-in providers span LLM APIs, dev tools, and SaaS, and the list grows over time. `Provider.list()` returns the full current set — names, hosts, and token shape:

<CodeGroup>
```typescript TypeScript
import { Provider } from "@superserve/sdk"

const providers = await Provider.list()
for (const p of providers) {
  console.log(p.name, p.hosts)  // "anthropic" ["api.anthropic.com"]
}
```

```python Python
from superserve import Provider

for p in Provider.list():
    print(p.name, p.hosts)  # "anthropic" ["api.anthropic.com"]
```
</CodeGroup>

## Custom secrets

When there's no shortcut, define the auth yourself with `auth` and `hosts`. `auth` and `provider` are mutually exclusive — pick one.

The `auth.type` controls how the credential is attached to outbound requests. Code in the sandbox sends the [stand-in token](/secrets/binding) where the credential goes, and the platform replaces it with the real value:

| `type` | Fields | Code in the sandbox sends | The upstream host receives |
|---|---|---|---|
| `bearer` | none | `Authorization: Bearer <stand-in>` | `Authorization: Bearer <value>` |
| `api-key` | `header`, optional `prefix` | `<header>: <prefix><stand-in>` | `<header>: <prefix><value>` |
| `basic` | optional `username` | HTTP Basic with the stand-in as the password | `Authorization: Basic <base64(username:value)>` |
| `custom` | `headers` | the stand-in in one of the `headers` | every header in `headers`, with `{{ value }}` replaced by the value |

The platform replaces the stand-in only in the place the auth type expects. A stand-in in any other header, or an `api-key` stand-in sent without its `prefix`, reaches the upstream host unchanged. For every field, see the [`SecretAuth` reference](/sdk-reference/secret#secretauth).

### Bearer token

<CodeGroup>
```typescript TypeScript
await Secret.create({
  name: "hf-token",
  value: process.env.HF_TOKEN!,
  hosts: ["huggingface.co"],
  auth: { type: "bearer" },
})
// In the sandbox: curl -H "Authorization: Bearer $HF_TOKEN" https://huggingface.co/api/whoami-v2
```

```python Python
Secret.create(
    name="hf-token",
    value=os.environ["HF_TOKEN"],
    hosts=["huggingface.co"],
    auth={"type": "bearer"},
)
# In the sandbox: curl -H "Authorization: Bearer $HF_TOKEN" https://huggingface.co/api/whoami-v2
```
</CodeGroup>

### API key header

`header` names the header. `prefix` is optional text before the value. Code in the sandbox must send the same prefix in front of the stand-in.

<CodeGroup>
```typescript TypeScript
await Secret.create({
  name: "pagerduty-key",
  value: process.env.PAGERDUTY_API_KEY!,
  hosts: ["api.pagerduty.com"],
  auth: { type: "api-key", header: "Authorization", prefix: "Token token=" },
})
// In the sandbox: curl -H "Authorization: Token token=$PAGERDUTY_API_KEY" https://api.pagerduty.com/users/me
```

```python Python
Secret.create(
    name="pagerduty-key",
    value=os.environ["PAGERDUTY_API_KEY"],
    hosts=["api.pagerduty.com"],
    auth={"type": "api-key", "header": "Authorization", "prefix": "Token token="},
)
# In the sandbox: curl -H "Authorization: Token token=$PAGERDUTY_API_KEY" https://api.pagerduty.com/users/me
```
</CodeGroup>

### HTTP Basic

The secret value is the password. Set `username` to send a fixed username; it replaces the username in the request. Without `username`, the platform keeps the username the request sends, or uses `x` when there is none.

<CodeGroup>
```typescript TypeScript
await Secret.create({
  name: "jira-token",
  value: process.env.JIRA_API_TOKEN!,
  hosts: ["your-team.atlassian.net"],
  auth: { type: "basic", username: "you@example.com" },
})
// In the sandbox: curl -u "you@example.com:$JIRA_API_TOKEN" https://your-team.atlassian.net/rest/api/3/myself
```

```python Python
Secret.create(
    name="jira-token",
    value=os.environ["JIRA_API_TOKEN"],
    hosts=["your-team.atlassian.net"],
    auth={"type": "basic", "username": "you@example.com"},
)
# In the sandbox: curl -u "you@example.com:$JIRA_API_TOKEN" https://your-team.atlassian.net/rest/api/3/myself
```
</CodeGroup>

### Custom headers

Use `custom` when the value goes in more than one header, or in a format the other types don't cover. `headers` maps each header name to a template, and every template must contain `{{ value }}`. Up to 8 headers. When a request carries the stand-in in one of these headers, the platform sets all of them. For example, a Supabase project's REST API reads the key from both `apikey` and `Authorization`:

<CodeGroup>
```typescript TypeScript
await Secret.create({
  name: "supabase-key",
  value: process.env.SUPABASE_KEY!,
  hosts: ["your-project.supabase.co"],
  auth: {
    type: "custom",
    headers: { apikey: "{{ value }}", Authorization: "Bearer {{ value }}" },
  },
})
// In the sandbox: curl -H "apikey: $SUPABASE_KEY" https://your-project.supabase.co/rest/v1/todos
```

```python Python
Secret.create(
    name="supabase-key",
    value=os.environ["SUPABASE_KEY"],
    hosts=["your-project.supabase.co"],
    auth={
        "type": "custom",
        "headers": {"apikey": "{{ value }}", "Authorization": "Bearer {{ value }}"},
    },
)
# In the sandbox: curl -H "apikey: $SUPABASE_KEY" https://your-project.supabase.co/rest/v1/todos
```
</CodeGroup>

### Per-host auth

A single secret can authenticate differently per host — useful when one credential works across, say, a REST API and a git endpoint:

<CodeGroup>
```typescript TypeScript
await Secret.create({
  name: "github-token",
  value: "ghp_...",
  hosts: ["api.github.com", "github.com"],
  auth: {
    perHost: [
      { hosts: ["api.github.com"], type: "bearer" },
      { hosts: ["github.com"], type: "basic", username: "x-access-token" },
    ],
  },
})
```

```python Python
Secret.create(
    name="github-token",
    value="ghp_...",
    hosts=["api.github.com", "github.com"],
    auth={
        "per_host": [
            {"hosts": ["api.github.com"], "type": "bearer"},
            {"hosts": ["github.com"], "type": "basic", "username": "x-access-token"},
        ]
    },
)
```
</CodeGroup>

<Note>
`hosts` accepts wildcards (`*.example.com`), but not a whole top-level domain like `*.com`. A wildcard matches subdomains, not the domain itself — list both `example.com` and `*.example.com` if you need each.
</Note>

## Rotation

Replace a secret's value without recreating it. Bound sandboxes keep their environment variable; the new value is used on subsequent requests — no redeploy, no restart. The change usually reaches bound sandboxes within seconds. Propagation is best-effort, so a sandbox can keep sending the old value for up to about a minute.

<CodeGroup>
```typescript TypeScript
const secret = await Secret.get("openai-prod")
await secret.rotate(newKey)
```

```python Python
secret = Secret.get("openai-prod")
secret.rotate(value=new_key)
```
</CodeGroup>

## List and delete

<CodeGroup>
```typescript TypeScript
const secrets = await Secret.list()

await Secret.deleteByName("openai-prod")
// or, from an instance:
await secret.delete()
```

```python Python
secrets = Secret.list()

Secret.delete_by_name("openai-prod")
# or, from an instance:
secret.delete()
```
</CodeGroup>

<Warning>
Deleting a secret revokes it **everywhere it's bound**. Requests that rely on it usually start failing within seconds; propagation is best-effort, so a sandbox can keep using the credential for up to about a minute. The environment variable stays, but its stand-in token no longer works. If you only want to change the value, [rotate](#rotation) instead.
</Warning>
