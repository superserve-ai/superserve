By default, a sandbox gets its template's size. If the template has a size range, you can instead choose `vcpu` and/or `memoryMib` within it when you create the sandbox, and the sandbox stays at that size. One template can then serve a small sandbox for a quick script and a large one for a build.

A size range is not the same as growth. A size range lets each sandbox pick its size once, at create. Growth (`vcpuMax` / `memoryMaxMib`) lets a running sandbox grow with load; see [Memory resizing](/sandbox/live-memory-resizing) and [CPU resizing](/sandbox/live-cpu-resizing).

## Build a template with a size range

Set `sizeRange` / `size_range` on the template. The range starts at the template's `vcpu` and `memoryMib`, and goes up to `vcpuMax` and `memoryMaxMib` inside `sizeRange`. Set one or both.

<CodeGroup>

```typescript TypeScript
import { Template } from "@superserve/sdk"

const template = await Template.create({
  name: "my-env",
  from: "python:3.11",
  vcpu: 1,
  memoryMib: 2048,
  sizeRange: { vcpuMax: 4, memoryMaxMib: 8192 },
})
await template.waitUntilReady()
```

```python Python
from superserve import Template, TemplateSizeRange

template = Template.create(
    name="my-env",
    from_="python:3.11",
    vcpu=1,
    memory_mib=2048,
    size_range=TemplateSizeRange(vcpu_max=4, memory_max_mib=8192),
)
template.wait_until_ready()
```

```bash CLI
superserve template create my-env --from python:3.11 \
  --vcpu 1 --memory 2G \
  --size-range-vcpu-max 4 --size-range-memory-max 8G
```

</CodeGroup>

With the [MCP server](/integrations/mcp), pass `size_range` to `sandbox_template_create`.

The maximums follow the same rules as growth: greater than the base, at most 4 times it, within your plan's limits, and for memory a multiple of 128 MiB above `memoryMib`. A vCPU maximum is at most 32.

Sandboxes that don't choose a size get the template's base size. To also let those sandboxes grow with load, set `vcpuMax` / `memoryMaxMib` on the template too, equal to the size range's maximum. A sandbox that chooses a size never grows.

The template reports its range:

<CodeGroup>

```typescript TypeScript
console.log(template.vcpu, template.sizeRange?.vcpuMax) // 1 4
```

```python Python
print(template.vcpu, template.size_range.vcpu_max)  # 1 4
```

</CodeGroup>

## Choose a size

Pass `vcpu`, `memoryMib` / `memory_mib`, or both.

<CodeGroup>

```typescript TypeScript
import { Sandbox } from "@superserve/sdk"

const sandbox = await Sandbox.create({
  name: "build",
  fromTemplate: "my-env",
  vcpu: 3,
  memoryMib: 6144,
})
```

```python Python
from superserve import Sandbox

sandbox = Sandbox.create(
    name="build",
    from_template="my-env",
    vcpu=3,
    memory_mib=6144,
)
```

```bash CLI
superserve sandbox create --name build --template my-env --vcpu 3 --memory 6G
```

</CodeGroup>

With the [MCP server](/integrations/mcp), pass `vcpu` and `memory_mib` to `sandbox_create`.

- **`vcpu`**: whole vCPUs from the template's `vcpu` to its `sizeRange.vcpuMax`.
- **`memoryMib`**: MiB from the template's `memoryMib` to its `sizeRange.memoryMaxMib`, in 2 MiB steps from the minimum. For a 2048–8192 MiB range, 6144 works and 6145 doesn't.
- Both ends of the range are included. Values must also be within your plan's limits. See [Resource limits](/templates/build-spec#resource-limits).

A fixed size holds through pause and resume. A resource you leave out keeps the template's default. In the example above, passing only `vcpu: 3` would give 3 vCPU and the template's 2048 MiB of memory.

The sandbox's info shows no maximum for a fixed dimension:

<CodeGroup>

```typescript TypeScript
const info = await sandbox.getInfo()
console.log(info.vcpuCount, info.vcpuMax) // 3 undefined
console.log(info.memoryMib, info.memoryMaxMib) // 6144 undefined
```

```python Python
info = sandbox.get_info()
print(info.vcpu_count, info.vcpu_max)  # 3 None
print(info.memory_mib, info.memory_max_mib)  # 6144 None
```

</CodeGroup>

## Snapshot copies

A sandbox created from a [snapshot](/sandbox/snapshots) keeps the original sandbox's size, including any range it grows in. You can also choose a size with `fromSnapshot` / `from_snapshot`:

- **`vcpu`** works when the original sandbox came from a template with a vCPU size range. The snapshot records that range, and the copy can take any count in it. For a snapshot of a 2 vCPU sandbox from a 1–4 vCPU template, 1, 3 and 4 all work.
- **`memoryMib`** works when the original sandbox had a fixed memory size. The copy can take any size in the snapshot's memory range, in 2 MiB steps from the minimum.

<CodeGroup>

```typescript TypeScript
const copy = await Sandbox.create({
  name: "bigger-copy",
  fromSnapshot: snapshot,
  vcpu: 4,
})
```

```python Python
copy = Sandbox.create(
    name="bigger-copy",
    from_snapshot=snapshot,
    vcpu=4,
)
```

```bash CLI
superserve sandbox create --name bigger-copy --snapshot <snapshot-id> --vcpu 4
```

</CodeGroup>

A snapshot of a copy records the same range, so a copy of a copy can choose again.

## Errors

| Status | Error | When |
| --- | --- | --- |
| `400` | `ValidationError` | The value is outside the template's or snapshot's range, or the template has no size range for that resource. System templates such as `superserve/base` have none. |
| `400` | `ValidationError` | `vcpu` with a snapshot that has no recorded CPU range, for example one from a system template. |
| `400` | `ValidationError` | `memoryMib` with a snapshot of a sandbox that didn't have a fixed memory size. |
| `402` | `BillingError` with code `sandbox_exceeds_plan_limits` | The value is within range but above your plan's limits. See [Billing errors](/errors#billing-errors-402). |
| `409` | `ConflictError` | The template was built before custom sizes were available. [Rebuild it](/templates/lifecycle), or leave out `vcpu` and `memoryMib`. |
| `429` | `RateLimitError` with code `host_capacity` | There's no capacity for that size right now. Retry after a short wait. |

## Billing

A fixed size is billed at that size while the sandbox is active. A resource that grows with load is billed as described in [CPU resizing](/sandbox/live-cpu-resizing#billing) and [Memory resizing](/sandbox/live-memory-resizing#billing).
