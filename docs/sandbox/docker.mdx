Every Superserve sandbox is a full Firecracker microVM with its own kernel, so Docker runs **inside** the sandbox the same way it does on any Linux machine: install it, start the daemon, and use `docker` as usual.

## 1. Bake Docker into a template

Install Docker at build time with the official install script, so every sandbox starts with it. [Templates](/templates/overview) snapshot this, so nothing is reinstalled when a sandbox launches. The sizes below fit every plan; raise `diskMib` if you pull large images (see [resource limits](/templates/build-spec#resource-limits)).

<CodeGroup>
```typescript TypeScript
import { Template } from "@superserve/sdk"

const template = await Template.create({
  name: "docker",
  from: "ubuntu:24.04",
  vcpu: 2,
  memoryMib: 2048,
  diskMib: 8192,
  steps: [
    { run: "apt-get update && apt-get install -y curl ca-certificates" },
    { run: "curl -fsSL https://get.docker.com -o /tmp/get-docker.sh && sh /tmp/get-docker.sh" },
  ],
})

await template.waitUntilReady()
```

```python Python
from superserve import Template, RunStep

template = Template.create(
    name="docker",
    from_="ubuntu:24.04",
    vcpu=2,
    memory_mib=2048,
    disk_mib=8192,
    steps=[
        RunStep(run="apt-get update && apt-get install -y curl ca-certificates"),
        RunStep(run="curl -fsSL https://get.docker.com -o /tmp/get-docker.sh && sh /tmp/get-docker.sh"),
    ],
)

template.wait_until_ready()
```
</CodeGroup>

## 2. Start the Docker daemon

Create a sandbox from the template and start `dockerd` in the background, then wait until it answers. `run()` doesn't throw on a non-zero exit, so check that the daemon came up; the request timeout is longer than the 30-second wait so that check is reached.

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "@superserve/sdk"

const sandbox = await Sandbox.create({ name: "docker-box", fromTemplate: "docker" })

const started = await sandbox.commands.run(
  "nohup dockerd > /var/log/dockerd.log 2>&1 & " +
    "timeout 30 sh -c 'until docker info > /dev/null 2>&1; do sleep 1; done'",
  { timeoutMs: 60_000 },
)
if (started.exitCode !== 0) {
  throw new Error("dockerd did not start; see /var/log/dockerd.log")
}
```

```python Python
from superserve import Sandbox

sandbox = Sandbox.create(name="docker-box", from_template="docker")

started = sandbox.commands.run(
    "nohup dockerd > /var/log/dockerd.log 2>&1 & "
    "timeout 30 sh -c 'until docker info > /dev/null 2>&1; do sleep 1; done'",
    timeout_seconds=60,
)
if started.exit_code != 0:
    raise RuntimeError("dockerd did not start; see /var/log/dockerd.log")
```
</CodeGroup>

## 3. Use it

Run containers, build images, and use Compose as you would anywhere else. Published ports are reachable from inside the sandbox, and containers can reach the internet.

<CodeGroup>
```typescript TypeScript
await sandbox.commands.run("docker run --rm hello-world")

await sandbox.commands.run("docker run -d --name web -p 8080:80 nginx:alpine")
const page = await sandbox.commands.run("curl -s localhost:8080")
console.log(page.stdout)
```

```python Python
sandbox.commands.run("docker run --rm hello-world")

sandbox.commands.run("docker run -d --name web -p 8080:80 nginx:alpine")
page = sandbox.commands.run("curl -s localhost:8080")
print(page.stdout)
```
</CodeGroup>

Running containers are part of the sandbox, so they keep running across a [pause and resume](/sandbox/lifecycle).

<Note>
Commands run without `HOME` set. If the Docker CLI warns that it can't load its config, prefix the command with `HOME=/root`.
</Note>
