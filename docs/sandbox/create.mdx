`Sandbox.create()` boots a fresh VM and returns when it's ready to use. There's no readiness check or polling - the returned instance is already `active`.

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "@superserve/sdk"

const sandbox = await Sandbox.create({ name: "data-analyzer" })
```

```python Python
from superserve import Sandbox

sandbox = Sandbox.create(name="data-analyzer")
```
</CodeGroup>

## With options

Attach metadata tags, inject environment variables, cap the active lifetime, or lock down network egress at creation time.

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "@superserve/sdk"

const sandbox = await Sandbox.create({
  name: "data-analyzer",
  timeoutSeconds: 3600,
  metadata: { env: "prod", owner: "agent-7" },
  envVars: { LOG_LEVEL: "debug" },
  // "openai-prod" must already exist, or create() fails with secret_not_found
  secrets: { OPENAI_API_KEY: "openai-prod" },
  network: {
    // the two IPs are the sandbox's DNS resolvers; deny-all blocks them too
    allowOut: ["api.openai.com", "*.github.com", "1.1.1.1/32", "8.8.8.8/32"],
    denyOut: ["0.0.0.0/0"],
  },
})
```

```python Python
from superserve import Sandbox, NetworkConfig

sandbox = Sandbox.create(
    name="data-analyzer",
    timeout_seconds=3600,
    metadata={"env": "prod", "owner": "agent-7"},
    env_vars={"LOG_LEVEL": "debug"},
    # "openai-prod" must already exist, or create() fails with secret_not_found
    secrets={"OPENAI_API_KEY": "openai-prod"},
    network=NetworkConfig(
        # the two IPs are the sandbox's DNS resolvers; deny-all blocks them too
        allow_out=["api.openai.com", "*.github.com", "1.1.1.1/32", "8.8.8.8/32"],
        deny_out=["0.0.0.0/0"],
    ),
)
```
</CodeGroup>

Each secret in `secrets` must already exist in your team. [Create the secret](/secrets/create) first: if it does not exist, `Sandbox.create()` raises a `ValidationError` with code `secret_not_found` (HTTP `400`) and no sandbox is created.

<Note>
Use **`secrets`** for credentials, not `envVars`. A secret binds an env var to a stored credential and attaches the real value to outbound requests — the real credential never enters the sandbox. See [Secrets](/secrets/overview).
</Note>

## Common options

| Option | Type | Description |
|---|---|---|
| `name` | `string` | **Required.** Human-readable sandbox name. |
| `timeoutSeconds` / `timeout_seconds` | `number` | Auto-pause after this many seconds of active time (per session; re-armed on resume). See [Lifecycle](/sandbox/lifecycle#auto-pause). |
| `vcpu` | `number` | Fixed vCPU count within the template's or snapshot's CPU range. See [Custom size](/sandbox/size). |
| `memoryMib` / `memory_mib` | `number` | Fixed memory in MiB within the template's or snapshot's memory range. See [Custom size](/sandbox/size). |
| `idleTimeoutSeconds` / `idle_timeout_seconds` | `number` | Auto-pause after this many seconds with no activity (60 to 604800). Requires SDK 0.11.6+. See [Lifecycle](/sandbox/lifecycle#idle-timeout). |
| `autoDeleteSeconds` / `auto_delete_seconds` | `number` | Delete the sandbox once continuously paused for this many seconds. See [Lifecycle](/sandbox/lifecycle#auto-delete). |
| `metadata` | `Record<string, string>` | String tags. See [Metadata](/sandbox/metadata). |
| `envVars` / `env_vars` | `Record<string, string>` | Env vars applied to every process. See [Environment variables](/sandbox/environment-variables). |
| `network` | `NetworkConfig` | Egress allow/deny rules. See [Networking](/sandbox/networking). |

See the [Sandbox reference](/sdk-reference/sandbox#sandbox-create) for every option including `apiKey`, `baseUrl`, and `signal`.

## Create from a template

Boot a sandbox from a system or team template via `fromTemplate` (name, UUID, or `Template` instance).

<CodeGroup>

```typescript TypeScript
const sandbox = await Sandbox.create({
  name: "my-sandbox",
  fromTemplate: "superserve/python-3.11",  // name
})
```

```python Python
sandbox = Sandbox.create(
    name="my-sandbox",
    from_template="superserve/python-3.11",
)
```

</CodeGroup>

See [Templates overview](/templates/overview) for how to build your own.

## Size

By default, a sandbox uses its template's vCPU, memory and disk. If the template has a range, the sandbox starts at the minimum and grows with load.

To fix the size instead, pass `vcpu` and/or `memoryMib` / `memory_mib` within the template's range:

<CodeGroup>

```typescript TypeScript
// Default: the template's size
await Sandbox.create({ name: "default", fromTemplate: "my-env" })

// Custom size
await Sandbox.create({
  name: "custom",
  fromTemplate: "my-env",
  vcpu: 2,
  memoryMib: 2048,
})
```

```python Python
# Default: the template's size
Sandbox.create(name="default", from_template="my-env")

# Custom size
Sandbox.create(name="custom", from_template="my-env", vcpu=2, memory_mib=2048)
```

</CodeGroup>

See [Custom size](/sandbox/size) for building a template with a range and choosing a size for snapshot copies.
