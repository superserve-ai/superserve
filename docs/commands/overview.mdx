Run any shell command inside a sandbox using `sandbox.commands.run()`.

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "@superserve/sdk"

const sandbox = await Sandbox.create({
  name: "data-analyzer",
  fromTemplate: "superserve/python-3.11",
})
await sandbox.files.write("/home/user/analyze.py", "print(sum(range(10)))")
const result = await sandbox.commands.run("python /home/user/analyze.py")
console.log(result.stdout)

await sandbox.kill()
```

```python Python
from superserve import Sandbox

sandbox = Sandbox.create(name="data-analyzer", from_template="superserve/python-3.11")
sandbox.files.write("/home/user/analyze.py", "print(sum(range(10)))")
result = sandbox.commands.run("python /home/user/analyze.py")
print(result.stdout)

sandbox.kill()
```
</CodeGroup>

<Note>
This page covers `run()`. If you need to send input to a process while it runs, like a REPL, [`spawn()`](/commands/sessions) keeps the session open instead.
</Note>

<Note>
Using `AsyncSandbox`? The same methods are there, awaitable. See the [Sandbox reference](/sdk-reference/sandbox).
</Note>

## Handling exit codes

`run()` doesn't throw on a non-zero exit code. Check `exitCode` on the result yourself.

<CodeGroup>
```typescript TypeScript
const result = await sandbox.commands.run("exit 42")
if (result.exitCode !== 0) {
  console.error(`Command failed: ${result.stderr}`)
}
```

```python Python
result = sandbox.commands.run("exit 42")
if result.exit_code != 0:
    print(f"Command failed: {result.stderr}")
```
</CodeGroup>

## Working directory and environment

Pass `cwd` and `env` to control the execution context.

<CodeGroup>
```typescript TypeScript
const result = await sandbox.commands.run("python script.py", {
  cwd: "/app",
  env: { PORT: "3000", DEBUG: "1" },
  timeoutMs: 60_000,
})
```

```python Python
result = sandbox.commands.run(
    "python script.py",
    cwd="/app",
    env={"PORT": "3000", "DEBUG": "1"},
    timeout_seconds=60,
)
```
</CodeGroup>

<Note>
Watch the units: TypeScript takes `timeoutMs` (milliseconds), Python takes `timeout_seconds` (seconds).
</Note>

Commands run as the template's user (the image's `USER`, or the template's `user` step). Pass `user` to run as someone else, like `docker exec -u`: a name or uid, optionally `:group`, e.g. `user: "root"` to install a package.

## Timeouts

The timeout is a hard limit on how long a command runs. When it's reached, the sandbox stops the command and `run()` returns with exit code `124`. It doesn't throw, so check the exit code. Output doesn't extend the limit: a command that keeps printing still stops on time.

<CodeGroup>
```typescript TypeScript
const result = await sandbox.commands.run("sleep 100", {
  timeoutMs: 5_000,
})
if (result.exitCode === 124) {
  console.error("Timed out after 5 seconds")
}
```

```python Python
result = sandbox.commands.run("sleep 100", timeout_seconds=5)
if result.exit_code == 124:
    print("Timed out after 5 seconds")
```
</CodeGroup>

What happens depends on the method and whether you set a timeout:

| | Timeout left off | Timeout set |
| --- | --- | --- |
| `run()` | The sandbox stops the command after 30 seconds. Without callbacks, the SDK also stops waiting at 30 seconds and throws `TimeoutError` / `SandboxTimeoutError`. With callbacks, the result has exit code `124`. | The sandbox stops the command at the limit, and the result has exit code `124`. |
| `spawn()` | No limit. The process runs until it exits or you kill it. | The sandbox stops the process at the limit, and `wait()` resolves with exit code `124`. |

Set a timeout on any `run()` that can take longer than 30 seconds. For a process with no fixed end, like a server, use [`spawn()`](/commands/sessions) without one.

<Note>
TypeScript rounds `timeoutMs` up to whole seconds. `run()` treats `timeoutMs: 0` the same as leaving it out, and throws `ValidationError` for a value that is negative, not finite, or out of range.
</Note>

### Long-running commands

A `run()` without callbacks gets no response until the command ends. If a command runs for more than a few minutes, the connection can close before the result arrives:

- **TypeScript on Node.js:** Node's built-in `fetch` waits at most 300 seconds for a response. A `run()` without callbacks that runs longer fails at 300 seconds with `SandboxError: Network error: fetch failed` (the error's `cause` has code `UND_ERR_HEADERS_TIMEOUT`), even when `timeoutMs` is longer.
- **Python:** some networks close a connection that has no traffic for a few minutes. Then `run()` raises `SandboxTimeoutError` at `timeout_seconds` plus 5 seconds, although the command finished.

In both cases, the command keeps running in the sandbox, but your code doesn't get its result. For a command that can run longer than 4 minutes, pass output callbacks. A streamed `run()` receives keepalive messages while the command runs, also when the command prints nothing, so the connection stays open:

<CodeGroup>
```typescript TypeScript
const result = await sandbox.commands.run("sleep 360 && echo done", {
  timeoutMs: 400_000,
  onStdout: (data) => process.stdout.write(data),
  onStderr: (data) => process.stderr.write(data),
})
console.log(result.exitCode) // 0
```

```python Python
import sys

result = sandbox.commands.run(
    "sleep 360 && echo done",
    timeout_seconds=400,
    on_stdout=lambda data: sys.stdout.write(data),
    on_stderr=lambda data: sys.stderr.write(data),
)
print(result.exit_code)  # 0
```
</CodeGroup>

If your process stops or loses its connection during a streamed `run()`, the sandbox stops the command. For a job that has to continue when your process goes away, start it in the background and check for an exit-code file:

<CodeGroup>
```typescript TypeScript
// Remove the exit file of an earlier job first.
await sandbox.commands.run(
  "rm -f /home/user/job.exit; " +
    "nohup sh -c 'sleep 360 && echo done; echo $? > /home/user/job.exit' > /home/user/job.log 2>&1 &",
)

let exitCode = ""
while (!exitCode) {
  await new Promise((resolve) => setTimeout(resolve, 10_000))
  const check = await sandbox.commands.run("cat /home/user/job.exit 2>/dev/null || true")
  exitCode = check.stdout.trim()
}
console.log(exitCode, await sandbox.files.readText("/home/user/job.log")) // 0 done
```

```python Python
import time

# Remove the exit file of an earlier job first.
sandbox.commands.run(
    "rm -f /home/user/job.exit; "
    "nohup sh -c 'sleep 360 && echo done; echo $? > /home/user/job.exit'"
    " > /home/user/job.log 2>&1 &"
)

exit_code = ""
while not exit_code:
    time.sleep(10)
    check = sandbox.commands.run("cat /home/user/job.exit 2>/dev/null || true")
    exit_code = check.stdout.strip()
print(exit_code, sandbox.files.read_text("/home/user/job.log"))  # 0 done
```
</CodeGroup>

The background job doesn't stop at a command timeout. It doesn't count as activity for the [idle timeout](/sandbox/lifecycle#idle-timeout), but each check is a command and does count. If you set an [auto-pause](/sandbox/lifecycle#auto-pause) timeout, make it longer than the job.

In TypeScript on Node.js, you can also keep a `run()` without callbacks. Install the [`undici`](https://www.npmjs.com/package/undici) package (`npm install undici`) and raise the `fetch` limits for the whole process:

```typescript TypeScript
import { Agent, setGlobalDispatcher } from "undici"

// Applies to every fetch call in this process.
setGlobalDispatcher(new Agent({ headersTimeout: 0, bodyTimeout: 0 }))

const result = await sandbox.commands.run("sleep 360 && echo done", {
  timeoutMs: 400_000,
})
```

`0` turns off these two `fetch` limits; the SDK still stops waiting 5 seconds after `timeoutMs`.

## Large output

Without callbacks, `run()` returns stdout and stderr in one JSON response, capped at 8 MiB of JSON-encoded output for both streams together. Characters that JSON escapes count for more than one byte (a `<` counts as six), so output with many of them is cut below 8 MiB of raw text. When the cap is reached, the sandbox drops the rest, sets `truncated` to `true` on the result, and appends a notice to `stderr`. The command itself still runs to the end.

<CodeGroup>
```typescript TypeScript
const result = await sandbox.commands.run("cat big.log")
if (result.truncated) {
  console.warn("Output was truncated")
}
```

```python Python
result = sandbox.commands.run("cat big.log")
if result.truncated:
    print("Output was truncated")
```
</CodeGroup>

For the full output, [stream it](/commands/streaming) with callbacks, or redirect it to a file in the sandbox and read the file. Streamed runs return everything, and `truncated` is always `false`.

For longer commands, [stream the output](/commands/streaming) as it runs. To send input to a process while it runs, [open a session](/commands/sessions).
