[QM](https://github.com/yc-software/qm) is Y Combinator's open-source, multiplayer agent harness for work. Your team talks to an agent in Slack and on the web; the agent works on a real computer with files, tools, and memory that persist between conversations. QM is designed to be self-hosted, and its [README](https://github.com/yc-software/qm#readme) walks through deploying it into your own cloud account.

**QM on Superserve** is the hosted option. Superserve runs QM for your team and gives the agent a Superserve sandbox as its computer, so you get a working stack in minutes without standing up a database, object storage, identity, or a sandbox backend yourself.

## What you get

- **A stack of your own.** Every team gets its own QM service, its own Postgres database, its own object-storage bucket, and its own service identity. Nothing is shared between teams except the cloud infrastructure underneath.
- **Sandboxes as agent computers.** The agent's computer is a durable Firecracker microVM. It is checkpointed between bouts of work and resumes with its disk intact, so the agent picks up where it left off.
- **Your model, your key.** Bring an Anthropic, OpenAI, or OpenRouter API key. It is stored in a secret manager and used only by your stack.
- **Your data stays yours.** The stack is a Postgres database plus object-storage bytes. You can export both and run QM yourself at any time. See [Export and leave](/qm/export-and-leave).
