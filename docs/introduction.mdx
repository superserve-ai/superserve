Each sandbox starts from a [template](/templates/overview) — a reusable base image with your dependencies baked in. See [Pause, resume, and delete](/sandbox/lifecycle) and [Snapshots and forks](/sandbox/snapshots) for how a sandbox keeps its state.

Start free, no card required. A new account gets a limited free trial for its first sandbox. See the [Quickstart](/quickstart).

<Tip>
  Use the menu at the top right of any page to add our docs as an MCP server
  in Claude Code, Cursor, or VS Code — giving your agent direct access to
  search and read Superserve documentation.
</Tip>

## What you can do

- **Create sandboxes** - go from `create()` to the first command in 0.41s median ([ComputeSDK, Oct 2026](https://github.com/computesdk/benchmarks/blob/415c7d727c70cdb5f1ee07c3a8caeca12e6f612b/results/burst_tti/2026-10-23.json))
- **Execute commands** - run shell commands and stream output
- **Read and write files** - transfer files to and from the sandbox filesystem
- **Pause and resume** - checkpoint sandbox state to disk and restore it later
- **Custom templates** - pre-bake team dependencies into base images and launch from them
- **Secrets** - give a sandbox an API key without the real value ever entering it
- **Network controls** - per-sandbox egress allow/deny rules, plus a log of every HTTP and HTTPS connection a sandbox made to a public address on ports 80 and 443
